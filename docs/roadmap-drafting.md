# 줄글 → 정식보고서, 그리고 여러 문서 → 새 보고서 (작업 계획)

2026-10-01 사용자 요청. 서식 변환(formal)은 거의 끝났고, 다음은 **내용을 보고서 문체·구조로 편집**하는 일이다.
제약: 사내 온프렘 LLM만 쓴다(외부 프론티어 모델보다 약함), 원문은 사외로 못 보낸다, 사용자는 결과를 자주 못 보낸다.

## 온프렘 LLM 사양 (2026-10-02 사용자)

Qwen3.6-27B-NVFP4, 컨텍스트 262,144토큰.
**속도 실측(2026-10-02, `tools/llm_speed.py`)**: 생성 약 115~145토큰/초, 입력 처리 1만 토큰대를 1.3초 이내(≥12k토큰/초).
기본이 추론(thinking) 모드라 1,500자→300자가 10.4초(추론이 1,500토큰을 다 씀, 답은 0자)인데 추론을 끄면(`chat_template_kwargs.enable_thinking=false`,
서버가 받음) 1.2초에 정상 답. 한국어 3만 자 ≈ 1.6만 토큰(약 1.9자/토큰, 반복 문장 기준) → 컨텍스트 전체는 약 40만 자 이상.
→ 문서 단위 호출은 수 초, 수만 토큰 입력도 수 초. `llm_polish`는 추론을 끄도록 바꿨다(켜려면 `DOC2REPORT_LLM_THINKING=1`).
긴 입력 찾기 시험 9/9 일치(2만·9.9만·26.3만 자, 앞·중간·뒤). 단 고유 사실 찾기라 낙관적 — 종합·비교는 별도 시험.
**1차 구현**: `drafting.py` + `doc2report draft` — A1~A2를 "문서 단위 배치 JSON"으로 구현(원문 문장 그대로, 요지 숫자 검증, 실패 시 규칙 기본 구조). 지금은 `--mode place`.

**2차 구현 (2026-10-03, B안 — 기본)**: LLM이 문장을 보고서 말투로 다시 쓰고 배열(대안 2개면 표)하며 줄마다 근거 문장 번호(src)를 단다. `transform/factcheck.py` + `rules/drafting.yaml`이 줄마다 숫자·금액·날짜·요일·영문·한자·방향·확정 여부를 근거 원문과 대조 → 걸리면 한 번 다시 쓰게 하고, 그래도 걸린 줄은 원문 문장 그대로. 생략한 문장·빠진 수치는 --report에. 문체 규칙은 [drafting-answers-analysis.md](drafting-answers-analysis.md)(정답 5건). 채점: `tools/score_drafting.py`.
- **줄글 한 편 전체(1,000~2,000자)는 한 번에 보내도 된다.** "문장 하나씩만" 시키던 제약을 "문서 하나를 한 번에, 출력은 닫힌 JSON"으로
  넓힌다(A1 역할 라벨·A2 구조 배치를 문서 단위로). 검증(수치·고유명사 보존)은 그대로 파이썬이 한다.
- B단계 코퍼스: 컨텍스트가 넓어 소규모(수십 편)는 **검색 없이 통째로** 넣는 것이 가능하다. 다만 실제로 쓸 수 있는 길이는
  지시 준수가 유지되는 구간(긴 입력 시험으로 확인, 보수적으로 3~5만 토큰)이고 입력 처리 시간이 길어지니 BM25 색인은
  코퍼스가 커질 때를 대비한 대안으로 남긴다.
- 27B는 열린 글쓰기보다 **추출·분류·재배치**에 강하다 — 원문에 없는 사실을 만들지 않는 원칙과 맞는다.

## 설계 원칙 (이 로드맵 전체에 적용)

1. **규칙이 뼈대, LLM은 짧은 작업만.** 구조(절·항목·세부)와 서식은 파이썬 규칙이 정한다. LLM에는 한 번에 한 문장·한 덩어리,
   **닫힌 선택지(라벨)나 JSON**만 시킨다. 약한 모델일수록 열린 글쓰기는 줄인다.
2. **모든 LLM 결과는 파이썬이 검증한 뒤 채택한다.** 수치·날짜·고유명사·부정어가 원문과 같은지, 길이·종결이 규칙 안인지 센다.
   통과 못 하면 원문 유지 + `--report`에 이유(지금 문장 줄임이 이미 이 방식).
3. **원문에 없는 사실은 만들지 않는다.** 생성 기능(B단계)은 모든 수치·주장에 출처 문서를 단다.
4. **정답 쌍으로 잰다.** 줄글 → (사람이 쓴) 정식보고서 쌍을 몇 건 모아 두고 변환 결과와 자동 비교한다. 이게 없으면 "좋아졌나"를 못 안다.

## A단계 — 줄글을 정식보고서로 편집 (규칙 기반 + LLM 보조)

| 순서 | 할 일 | 방법 | 산출물 | 검증 |
|---|---|---|---|---|
| A0 | probe에 **구조·문체 통계** 보강 | 절당 □ 수, □당 - 수, 층별 문장 길이·종결·접속어, 숫자·날짜 표기, 첫 문장 유형 | probe 요약 절 | 합성 docx 테스트 + 사내 8건 1회 실행 |
| A1 | 줄글 → **문장 단위** 분해와 **역할 라벨** | 규칙: 접속어·수치·날짜·열거 신호. LLM(폐쇄 라벨: 배경·현황·문제·방안·효과·일정·참고)은 규칙이 애매한 문장만 | `Sentence(role, text)` 목록 | 정답 쌍에서 역할 일치율 |
| A2 | **구조 배치** | 역할 → 절(1.) / 항목(□) / 세부(-) / 참고(※) 매핑표(yaml). 항목 길이·개수 한도는 A0 실측으로 | `Document`(IR) | 구조 차이(절·항목 수) 비교 |
| A3 | **문체 규칙** | 개조식 종결(이미 `stylize_ko`), 한 줄 이내(좁히기 한도), 숫자·날짜 표기, 금지·권장 표현 사전(yaml) | 변환된 문장 + 변경 내역 | 층별 종결·길이 분포가 원본 분포 안인지 |
| A4 | **LLM 재작성**(필요한 문장만) | 입력 1문장 + 목표(층·최대 글자 수·종결), 출력 1문장. 수치·고유명사 보존 검사, 실패 시 원문 | `표현 줄임`과 같은 구조로 확장 | 보존 검사 통과율, 채택률 |
| A5 | **점검기(lint)** | 변환 결과를 채점: 한 줄 초과, 종결 불일치, 단계 불일치, 수치 누락 → 경고만(막지 않음) | `--report`의 점검 절 | 정답 쌍 대비 위반 건수 |

진행 방식: A0 → (사용자가 probe 1회 실행) → A1·A2를 규칙만으로 먼저 → 정답 쌍으로 측정 → 부족한 자리에만 LLM(A4).

## B단계 — 여러 문서 → 새 내용·요약 보고서

| 순서 | 할 일 | 방법 |
|---|---|---|
| B1 | **코퍼스 색인** | 과거 문서를 절·항목 단위 조각으로 쪼개 저장(메타: 연도·주제·표 유무). 검색은 BM25(순수 파이썬, 오프라인) — 임베딩 모델 없이도 되게 |
| B2 | **요약** | 조각별 요약(map) → 절별 합치기(reduce). 한 번에 보내는 양을 모델 컨텍스트 안으로 자름. 수치는 원문 그대로 인용하고 출처 태그를 단다 |
| B3 | **초안 생성** | 개요(템플릿: 배경–현황–방안–계획, 문서 유형별 yaml) → 절별로 B1 검색 + 생성 → **A단계 파이프라인으로 서식·문체 정리** |
| B4 | **출처·검수** | 모든 문장에 출처 문서·위치, 원문에 없는 수치는 경고. 사용자 검수용 대조표 출력 |

B는 A의 문체·검증 장치를 그대로 재사용한다. A가 안정되기 전에는 시작하지 않는다.

## 지금 필요한 것 (사용자)

1. **probe**: 서식 값은 사용자 지시가 우선이라 다시 검증하지 않는다. A0에서 더하는 구조·문체 통계(절당 □ 수, 층별 문장 길이·종결 등)만 필요할 때 1회 실행한다.
   표 머리 음영(테마색 수정 후 재확인), 칸 테두리 실제 굵기(1.5pt 확인), 줄 폭 사용률(좁히기 0.4pt 여유를 실측으로 대체),
   주석 상자 위치·높이, 말머리 앞 공백 분포. **A0에서 구조·문체 통계를 더해 한 번에 받는 것을 권한다.**
2. **정답 쌍 3~5건**(가상화해도 됨): 같은 내용의 줄글(메모·메일 형태)과 사람이 쓴 정식보고서 → 이것이 A단계의 시험지다.
3. 온프렘 LLM의 **컨텍스트 길이·응답 속도**(대략): B단계 조각 크기를 정하는 데 필요하다.
4. 보고서 **유형**(예: 현황 보고, 방안 검토, 결과 보고)이 몇 가지인지, 유형별로 절 구성이 다른지.
